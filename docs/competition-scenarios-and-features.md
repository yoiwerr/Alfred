# 智能体拟开发场景及功能

> 项目：阿福 — AI 执行管家
>
> 用于比赛申报材料

---

## 一、产品定位

**阿福**是一个住在开发者项目里的 AI 执行管家。他不是聊天机器人——他理解你的代码库，记得你的偏好，能独立完成从需求理解到部署上线的完整闭环。你负责做关键决策，他负责把一切搞定。

核心转变：

```
传统 AI 助手:  你问 → 它答 → 你执行
阿福:          你说了方向 → 它感知 → 它分析 → 它执行 → 它验证 →
              关键节点精准打断你 → 你决策 → 它继续执行
```

## 二、核心场景

### 场景一：日常开发流 —「从一句话到上线PR」

**用户怎么说：**
> "帮我加个用户登录功能"

**阿福做什么：**

| 步骤 | 阿福的行为 | 对应能力 |
|------|-----------|---------|
| 1. 理解上下文 | 自动扫描项目：FastAPI + React，已有 JWT 中间件，数据库是 PostgreSQL | 代码库深度理解 |
| 2. 补齐信息 | 发现关键空缺 → 精准追问：「用邮箱+密码还是手机验证码？要不要加 OAuth？」 | 智能追问 |
| 3. 自主规划 | 拆解任务：后端路由 → 中间件配置 → 前端表单 → 单元测试 → 集成测试 | Planner + 执行计划 |
| 4. 并行执行 | 后端 Agent + 前端 Agent 同时开工，彼此不阻塞 | Multi-Agent 并行 |
| 5. 自检验证 | 写完代码 → 自动运行测试 → 发现一个测试挂了 → 自动分析原因 → 修复 → 再跑 → 通过 | Execute → Checkpoint → Retry |
| 6. 质量审查 | Reflector 检查：代码风格对不对？有没有安全漏洞？密码有没有 hash？ | 自动 Code Review |
| 7. 提交产出 | 创建 PR，附带变更摘要和测试结果 → 「少爷，做好了。您看看还有什么要调整的？」 | Git 集成 + 主动汇报 |

**用户感知：** 早上说了句话，喝了杯咖啡回来，PR 已经等着 review 了。

---

### 场景二：运维保障流 —「CI 挂了？我已经修了」

**用户怎么说：**
> （用户什么都没说——阿福自己发现的）

**阿福做什么：**

| 步骤 | 阿福的行为 | 对应能力 |
|------|-----------|---------|
| 1. 自动感知 | GitHub Webhook 收到 CI 失败通知 → 阿福被唤醒 | 事件驱动 |
| 2. 定位根因 | 抓取 CI 日志 → 分析堆栈 → 定位到第三方支付 API 超时 | 日志分析 |
| 3. 判断责任 | 不是你的代码问题，是外部服务抖动。无需惊动你 | 自主决策分级（L1） |
| 4. 尝试修复 | 自动重试 CI → 成功。「就是个临时网络波动」 | 自主执行 |
| 5. 记录+建议 | 标记事件到知识库 → 「少爷，这个 API 最近 3 天超时了 2 次。建议加个指数退避重试。要我来吗？」 | 模式识别 + 主动建议 |

**用户感知：** 第二天早上才知道昨晚 CI 挂过——但阿福已经处理完了，附带一条优化建议。

---

### 场景三：技术调研流 —「帮我选个方案，不是丢链接」

**用户怎么说：**
> "我想把项目的 SSE 推送换成 WebSocket，但不确定有没有必要"

**阿福做什么：**

| 步骤 | 阿福的行为 | 对应能力 |
|------|-----------|---------|
| 1. 现状分析 | 扫描项目代码：现有 SSE 实现、消息频率、数据流向、用户量级 | 代码库理解 |
| 2. 知识库检索 | 从知识库召回 WebSocket vs SSE 的最佳实践和技术边界 | RAG 混合检索 |
| 3. 多维对比 | 输出：「你的场景是聊天消息推送——低频、单向、延迟不敏感。SSE 完全够用。WebSocket 会多 40% 的代码量和 2 天工时。建议不换。但如果未来要加实时协作编辑，那时候再换。」 | 结构化分析 |
| 4. 可执行 | 如果你还是要换——「好的，这是迁移方案。改动涉及 5 个文件，预计 3 小时。要我直接做吗？」 | 从调研到执行的无缝衔接 |

**用户感知：** 不是在跟搜索引擎聊天——它真的看了你的代码，给了针对你项目的判断，不是通用回答。

### 场景四：知识管理流 —「我忘了的事，它都记着」

**用户怎么说：**
> （持续进行，无需用户触发）

**阿福做什么：**

| 步骤 | 阿福的行为 | 对应能力 |
|------|-----------|---------|
| 每日总结 | 每天结束自动汇总：今天做了 3 个决策、修了 2 个 bug、新增了 1 个风险点 | 定时任务 + 语义摘要 |
| 每周周报 | 周五自动生成：本周完成 5 个 feature、技术债务变化、下周建议 | L2 滚动摘要 + 周报模板 |
| 跨会话记忆 | 三天前你说了「不要用 Redux」→ 今天讨论状态管理时阿福自动提醒：「根据您 3 天前的决策，Redux 已被排除。建议考虑 Zustand。」 | L3 语义事实 + PGVector 检索 |
| 知识沉淀 | 每次重要决策自动入知识库：「2026-07-20: 选型 FastAPI over Django，原因：轻量+异步+团队熟悉」 | 自动知识库更新 |
| 错误不犯两次 | 上次你说「这里不应该用硬编码」→ 之后每次生成 config 相关代码，自动用环境变量 | 反馈学习闭环 |

**用户感知：** 一个永远不会忘记的搭档。你三个月前随口说的偏好，三个月后它依然记得。

---

### 场景五：代码审查流 —「不只是找 bug，是直接修好」

**用户怎么说：**
> （git push 时自动触发）

**阿福做什么：**

| 步骤 | 阿福的行为 | 对应能力 |
|------|-----------|---------|
| 1. 多维审查 | 安全：SQL 注入？XSS？硬编码密钥？<br>性能：N+1 查询？未索引的列？<br>风格：命名规范？代码复用？ | Code Reviewer Agent |
| 2. 分级处理 | L1（空格/import 排序）：直接修了<br>L2（提取重复代码）：修了，出 diff 给你看<br>L3（SQL 在 10 万行时会慢）：标记，建议你亲自确认 | 自主决策分级 |
| 3. 验证修复 | 修完自动跑测试 → 测试通过 → 追加 commit → 「Review 完成。3 个 L1/L2 问题已修复，1 个 L3 问题需要您确认。」 | 修复→验证→汇报 |
| 4. 持续学习 | 你说过「这里其实不用改」→ 之后同类问题不再标记 | 从反馈中学习 |

**用户感知：** 代码一 push，过两分钟回来，简单问题已经修好了，复杂问题已经标好了——你只需要 focus 在真正需要判断的事情上。

## 三、功能矩阵

### 3.1 已实现能力（V3 当前版本）

| 功能 | 说明 | 技术实现 |
|------|------|---------|
| **智能意图识别** | 自动判断用户想做什么：写提示词？排任务？整理信息？审代码？ | LLM 分类 + 规则 fallback，6 种意图 |
| **结构化追问** | 信息不够时精准追问，不是笼统的「再说详细点」 | Planner JSON mode 提取维度 + 模板兜底 |
| **知识库检索** | 从手写知识库检索领域最佳实践 | Dense + BM25 → RRF → Rerank，5 步混合检索管道 |
| **ReAct 执行** | 需要时自动调用工具（搜索知识库/执行代码/查看文件） | LangGraph create_react_agent |
| **语义检查** | 执行中持续检查「方向有没有跑偏」 | Checkpoint 节点（独立于质量审查） |
| **质量审查** | 输出后自动审查：完整性、准确性、幻觉检测 | Reflector 节点，最多 2 次重试 |
| **三层上下文** | 记住对话历史，不会多轮后忘记 | L1 滑动窗口 + L2 滚动摘要 + L3 语义事实 |
| **会话记忆** | 跨会话保留关键信息（偏好/决策/约束） | PGVector 持久化 + 语义检索 |
| **流式输出** | SSE 实时推送响应 | EventSourceResponse |
| **用户反馈** | 👍👎 反馈收集 | PostgreSQL 存储 + 统计 |

### 3.2 拟开发能力（完成体）

| 功能 | 所属场景 | 说明 | 优先级 |
|------|---------|------|--------|
| **项目心智模型** | 开发/调研/审查 | 自动构建代码库的结构化理解——模块依赖、技术栈、关键文件、架构决策。不靠用户每次贴代码 | P0 |
| **自主决策分级** | 所有场景 | L1 自动执行（格式化/import整理）→ L2 建议+自动修（bug fix）→ L3 必须确认（API变更/删数据） | P0 |
| **Multi-Agent 协作** | 开发/审查 | Supervisor 分发任务 → Coder / Reviewer / Researcher / Writer 并行工作 → 结果汇总 | P0 |
| **长链自主执行** | 开发/运维 | 多步任务自主推进（规划→编码→测试→修复→测试→部署），关键节点暂停等待决策 | P0 |
| **事件驱动感知** | 运维/审查 | 接收 GitHub Webhook / CI 状态变更 → 自动触发分析 → 主动汇报 | P1 |
| **定时任务引擎** | 知识管理 | 每日/每周自动汇总、定期巡检代码库、自动生成周报 | P1 |
| **Git 深度集成** | 开发/审查 | 创建 PR、review 代码、合并分支，不是只读查看 | P1 |
| **反馈学习闭环** | 所有场景 | 👎反馈 → Badcase 收集 → 模式识别 → 规则更新 → Eval 验证 → 不犯第二次 | P1 |
| **主动通知** | 运维/知识管理 | Slack/飞书 Bot，有值得关注的事情主动推送，不是等你来问 | P2 |
| **跨项目知识迁移** | 调研/开发 | 在项目 A 学到的架构决策自动应用到项目 B | P2 |
| **多模态理解** | 开发/调研 | 截图→理解UI意图生成代码；白板草图→结构化方案；错误截图→自动定位 | P2 |
| **Human-in-the-Loop** | 开发/运维 | 关键操作（改生产配置、删除数据）必须人工审批后才执行 | P2 |

## 五、与同类产品的差异

| 维度 | 通用 AI 助手（ChatGPT/Claude） | AI 编码工具（Copilot/Cursor） | **阿福** |
|------|------------------------------|------------------------------|---------|
| 交互模式 | 问答式，单轮为主 | 补全式，行级协助 | **管家式**，长链自主执行 |
| 项目理解 | 零（每次复制粘贴上下文） | 当前文件/AST | **完整的代码库心智模型**，理解架构和依赖 |
| 记忆 | 当前对话窗口 | 无 | **跨会话持久记忆**，记住偏好和决策 |
| 主动性 | 无，完全被动 | 被动触发 | **事件驱动 + 定时巡检**，会主动告诉你 |
| 决策能力 | 给建议 | 给补全 | **分级自主决策**，小事直接做了，大事精准问你 |
| 执行深度 | 输出文本 | 补全代码行 | **从规划到部署的完整闭环** |
| 多 Agent | 无 | 无 | **Supervisor 分发 + 多专业 Agent 并行** |
